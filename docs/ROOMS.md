# 房间管理与密码

## 房间管理员

“房间设置”中勾选成员可授予房间管理员权限，取消勾选立即撤销。
管理员与房主均可改名、改密、管理管理员名单、选片、控制播放、切换模式、踢人及解散房间。
房主身份不可转移或被踢出；管理员不是站点后台管理员。
管理员名单保存在房间 JSON 的可选 `adminIds` 数组，旧数据缺失时按空名单读取。
离线不取消权限，设置页保留离线管理员以便撤权；踢出管理员同时撤销其权限。
管理员与房主一样无需房间密码即可加入；每次管理操作均重新读取 Redis 校验权限。
新增 `set_room_admins` 事件接收 `{ adminIds: string[] }`，最多 100 人，仅允许已有管理员或当前在线成员，复用会话校验、限流和串行写入。
发布顺序为兼容服务端、客户端；单实例部署需重启服务，无新增环境变量和离线迁移。
回退旧版时管理员字段会被忽略，旧版仍仅允许房主管理，不应回退到缺少密码校验的版本。

## 使用

- 片库侧栏使用紧凑图标分类，视频源单独分区。播放器右下角、原生控制条上方统一放置弹幕、聊天和全屏按钮。快捷键 `D` 切换弹幕、`C` 展开/收起聊天、`F` 进入/退出全屏，按钮悬浮提示显示对应按键；普通模式也可展开悬浮聊天。输入框、可编辑内容、中文输入法组合输入、按键长按及 Ctrl/Alt/Meta 组合键不会触发这些快捷键，模态对话框打开时也不触发。进入和退出全屏不改变播放同步行为。

- 首页和普通播放页的创建入口打开统一弹窗，可填写名称和可选密码；播放页默认填写影片名称，创建成功后继续带入可同步影片。
- 每个账号同时只能拥有一个尚未移除的房间，退出或断线不算移除。重复创建返回 `ROOM_ALREADY_OWNED` 和本人已有的 `roomId`，弹窗提供进入已有房间的入口，不覆盖原播放或密码。并发创建由单实例串行队列裁决。
- 旧数据已有多个房间时保留，不强制删除，但不能继续新建。房间被空房策略移除后才可再次创建；永驻或关闭自动清理的房间继续占用名额。

- 管理员直接访问 `/admin`，在“房间管理”查看房间与当前在线成员。成员列表不是历史访问记录，点击刷新获取新状态。
- 后台菜单分别展示运行概览、房间管理、视频源、站点配置和管理员账号。`/admin?view=rooms` 可直接打开房间管理，菜单状态支持刷新和浏览器前进/后退。
- 房间列表及编辑区提供“移除”，二次确认后删除房间、播放与聊天记录，即使永驻或有人在线也可移除。在线成员收到移除提示并退出房间，房主名额释放；旧数据有其他房间时仍不能重复创建。移除不可撤销，需从备份恢复。
- 房主可在观影页点击“解散房间”，确认后立即删除房间、播放和聊天记录，所有在线成员退出，房主也可重新创建房间。解散不可撤销。
- 全局空房清理时间默认为 `0`，表示不自动清理。每房可跟随全局、指定 1–43200 分钟，或设为永驻。
- 最后一位成员离开后开始计时；有人在线不会清理；永驻优先于所有时间配置。全局 `0` 不会取消单房独立时限。
- 服务每 30 秒检查空房，读取房间时也会检查过期状态。开启或缩短时限可能立即删除已经超时的空房，包括其中的聊天与播放状态，无法通过取消配置恢复。
- 创建房间时可以填写密码。房主在观影页“房间密码”中修改或取消；管理员也可在后台设置或取消。密码长度为 4–64 位，不提供明文查询。
- 邀请链接不携带密码。用户先登录，再输入房间密码；房主不需要输入自己房间的密码。
- 播放器左侧可设置房间播放模式：`自动连播`按当前影片的可同步集数顺序播放下一集，`单个播放`播放结束后暂停，`随机播放`从当前影片的其他可同步集数中随机选择下一集。该设置只由房主修改，并实时同步给房间成员；旧房间默认使用自动连播。
- 自动切集由在线房主的播放器驱动，房主离线时不会由服务端代替播放。最后一集、单集影片或随机模式没有其他可选集数时会暂停。服务端使用当前播放版本校验推进请求，重复结束事件或旧播放器事件不会覆盖新播放状态。
- 从首页或 `/rooms` 列表加入密码房间时，在当前页弹窗验证，成功后才跳转观影页；关闭或按 Escape 取消并停止该次加入重试。直接打开邀请链接时保留观影页的独立密码表单。已有有效授权或公开房间仍直接进入。
- 观影页左侧只保留片库分类和视频源菜单。在线成员在房间头部叠放头像（最多五个，超出显示数量），点击展开完整名单，显示房主和本人标记；头像缺失或加载失败显示名称首字。房主和其他成员均可查看，房主可以在成员名单中将其他成员移出房间。
- 房主可通过“房间设置”修改房间名称、设置或取消密码，以及切换播放模式。修改房间名称和播放模式会实时同步给在线成员。
- 在线成员列表显示地区；管理员在房间管理中可查看在线成员的服务端识别 IP 和设备标识。IP 只信服务端地址或显式配置的可信代理头，浏览器上报的地区仅用于展示。
- 头部成员、“邀请好友”和“房间密码”面板互斥显示，点击另一个按钮直接切换；再次点击、点击外部或按 Escape 收起。Escape 会将焦点返回对应按钮。
- 改密不踢当前在线成员，下一次加入或重连按新密码验证。成功验证后，服务端为当前登录会话保存最长七天的授权；登录失效、改密或主动退出房间后不再凭旧授权进入。浏览器不持久化密码。

## 接口与数据

管理员接口复用独立后台会话、写请求来源校验和限流：

- `GET /api/admin/rooms`：全局策略、房间和在线成员。
- `PUT /api/admin/room-policy`：`{ emptyMinutes: 0 }`，允许 0–43200 的整数。
- `PUT /api/admin/rooms/:id`：`permanent`、`emptyMinutes`（null 跟随全局）与可选 `password`；不传密码保持原值，空字符串取消密码。
- `DELETE /api/admin/rooms/:id`：移除房间，重复删除有效格式的房间 ID 仍返回成功。复用后台会话、来源校验和写入限流。新增 `room_removed` Socket 事件，仅发给该房间在线成员；客户端停止播放、聊天及自动重入。旧客户端下一次操作被服务端拒绝，刷新后无法再加入。

Socket 的 `create_room`、`join_room` 新增可选 `password`；新增房主或管理员可用的 `set_room_name`、`set_room_password`、`set_play_mode`、`kick_member`、`dissolve_room`，以及用于更新管理员名单的 `set_room_admins`。房间摘要追加 `adminIds`、`hasPassword`、`permanent`，不返回密码哈希。普通列表不暴露成员详情，密码房间也不暴露播放状态；公开房间的播放状态包含经过服务端校验的影片名称、集数和封面地址，用于房间卡片展示；成功加入后才返回房间聊天和成员。被移出的成员收到 `kicked`（`ROOM_KICKED`）事件并停止自动重连。

后台新增 `/api/admin/bans`，支持封禁或解除 IP、设备标识。封禁记录存储在 Redis，新增封禁后会踢出匹配的在线连接；HTTP 请求和 Socket 握手均由服务端拦截。设备标识使用 HttpOnly Cookie，不能由前端输入伪造。

房间摘要追加 `playMode`，取值为 `sequential`、`single` 或 `random`，缺失旧数据按 `sequential` 读取。新增房主专用 `set_play_mode` 和 `advance_playback`：后者必须携带当前 `expectedRevision`，服务端串行校验房主身份、房间模式和播放版本后才切换集数，失败返回 `STALE_PLAYBACK` 或 `PLAY_MODE_SINGLE`。

密码相关错误码包括 `ROOM_PASSWORD_REQUIRED`、`ROOM_PASSWORD_INVALID`、`ROOM_FORBIDDEN`、`RATE_LIMITED`；房间不存在为 `ROOM_NOT_FOUND`，配置无效为 `INVALID_ROOM_CONFIG`。密码尝试按账号与房间限制为每分钟十次。旧客户端仍可进入公开房间，无法输入密码的客户端会安全拒绝进入密码房间。

Redis 数据：

- `fishTV:room:policy` 保存全局 `emptyMinutes`，无 TTL。
- 原房间 JSON 追加 `permanent`、`emptyMinutes`、`emptySince`、`passwordHash`。密码使用随机盐和 scrypt 哈希，无明文存储。
- `fishTV:room:grant:<roomId>:<sessionDigest>` 保存密码哈希摘要，TTL 七天；键不含原始会话凭据。
- `fishTV:room:password-attempt:<digest>` 保存尝试次数，TTL 60 秒。
- 清理删除房间键及房间索引项，残留授权键自然到期。

旧房间字段按默认值读取，不需要离线迁移。读取时按本实例实际 Socket 连接校正残留成员；旧空房缺少计时时间时从首次检查开始计时，写回可重复执行。服务重启后，之前有人且未记录空房时间的房间从首次检查开始计时；已有空房时间的房间继续原计时。

## 部署与回滚

必须使用单 Node 实例。HTTP 管理、Socket 写操作与清理共用进程内串行队列，不是分布式锁；禁止多实例或滚动部署时让两个房间服务同时连接同一套房间 Redis 数据。

可选配置 `TRUST_PROXY=1` 和 `CLIENT_IP_HEADER`（例如 `CF-Connecting-IP`），仅在服务端前方有可信反向代理时启用；不配置时使用 Node 连接地址。发布前备份 Redis；停止旧 Node 服务后发布兼容服务端与客户端并重启，不能仅依赖前端热更新。确认后台列表、密码加入、断线重连、封禁踢出与空房清理，再开启非零清理时间。

日志提供 `policy_updated`、`admin_room_updated`、`owner_password_updated`、`password_accepted`、`password_denied`、`password_limited`、`empty_room_removed` 和失败事件，不记录密码。这些日志不是完整监控或告警系统；进程健康检查也不等于 Redis/上游深度健康检查。

回滚触发条件包括异常删房、密码验证异常和配置持久化失败。不要直接回滚到不校验房间密码的旧服务端，否则密码房间可能变为公开。应停止服务，恢复升级前 Redis 备份并部署对应旧版本，或使用保留密码校验的兼容修复版本。已经自动删除的房间只能从备份恢复。

发布记录由发布负责人填写版本、负责人、配置/迁移（本次无新增环境变量，房间字段按需兼容）、验收结果和回滚触发条件。
